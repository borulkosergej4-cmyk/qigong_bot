# CLAUDE.md

Руководство по кодовой базе для Claude Code. Актуально на **04.07.2026**.

## Что это

Бот-система для Telegram-канала и группы ВКонтакте, посвящённых **оздоровительному цигун и ушу** (@baguazhangspb, Санкт-Петербург). Ведёт канал и проводит занятия **Сергей** (ID 915727236).
Деплой: **Railway** (проект `distinguished-surprise`, автодеплой при пуше в `main`).
База данных: **Neon PostgreSQL** (отдельная от stremlenie_bot).

## Команды

```bash
pip install -r requirements.txt   # установка зависимостей
python run_all.py                  # локальный запуск всех сервисов
```

## Архитектура

### Четыре сервиса в одном процессе

`run_all.py` запускает всё параллельно через `asyncio.gather`:
1. **dashboard** — FastAPI на порту `$PORT` (Railway ждёт открытый порт)
2. **admin_bot.py** — Telegram-бот для Сергея (посты, Reels, контент-план)
3. **bot.py** — Telegram-бот Конфуций для клиентов
4. **vk_bot.py** — VK-бот Конфуций для клиентов

### Чат-бот Конфуций

Персонаж — Конфуций, наставник по оздоровительному цигун и ушу. Отвечает на вопросы о практике, ТКМ, расписании и записи на занятия.

**Где работает:**
- Telegram личка — полный диалог с кнопками меню
- Telegram группа (@baguazhangspb) — на любое сообщение от живого пользователя отвечает «Отвечу подробнее в личных сообщениях» + кнопка-ссылка в приватный чат. Бот должен быть **администратором** группы.
- VK — полный диалог в личных сообщениях группы

**База знаний (`data/knowledge.py → CONFUCIUS_PROMPT`):**
- Официальные программы цигун: Бадуаньцзин, У Цинь Си (五禽戏), И Цзинь Цзин, Да У (大舞), Даоинь
- ТКМ: 12 меридианов, 5 элементов, 10 ключевых точек самомассажа
- Анатомия и физиология цигун
- Стиль Багуачжан и Тайцзицюань
- Ссылки: Boosty (https://boosty.to/s.borulko), VK Донат (https://vk.com/donut/club162151764)

**Шесть целительных звуков (六字诀) в программу НЕ входят — Конфуций их не упоминает.**

### Агент-система (agents/base_agent.py)

`BaseAgent` хранит историю диалога (max 20 сообщений) на каждого `user_id`.

**Персистентная история (переживает рестарты Railway):** `ensure_loaded(user_id)` при первом обращении подгружает историю из таблицы `chat_history` (`data/database.py: load_chat_history`); после каждого ответа агента `_persist(user_id)` сохраняет её обратно (`save_chat_history`, upsert по `(user_id, source)`). Ключ источника (`source`) — `"telegram"` или `"vk"`, задаётся при создании `BaseAgent`.

**Приоритет провайдеров AI:**
1. **Claude Haiku** (`claude-haiku-4-5-20251001`) — основной. Требует `ANTHROPIC_API_KEY`.
2. **OpenRouter** (`google/gemma-2-27b-it:free` → `meta-llama/llama-3.3-70b-instruct:free`) — резерв.
3. **Groq** (`llama-3.3-70b-versatile` → `llama-3.1-8b-instant`) — финальный резерв.

**Постобработка (`_postprocess`):** снимает все `*` и `**` из ответов всех провайдеров, чтобы ссылки и текст приходили без markdown-звёздочек.

**Расписание:** если в запросе ключевые слова («расписани», «занятия», «когда» и др.) — автоматически подгружается расписание из Mobifitness API (клуб ID `2391` — тот же клуб, что у stremlenie_bot; Сергей Борулько ведёт «Оздоровительный цигун» в нём наряду с занятиями студии «Стремление», фильтруется по `TRAINER_FILTER = "Сергей"`): текущая + следующая неделя.

### Флоу записи клиента (bot.py и vk_bot.py)

1. Клиент пишет ключевое слово («записаться», «хочу попасть» и др.)
2. Конфуций спрашивает имя → телефон
3. Заявка сохраняется в БД через `asyncio.to_thread` (не блокирует event loop)
4. Уведомление Сергею через `ADMIN_BOT_TOKEN`
5. Подтверждение: «Записал вас, {name}. Сергей свяжется с вами в ближайшее время.»

### Приветствие новых участников группы (16.07.2026)
Раньше при каждом вступлении в группу Telegram присылал служебное сообщение, на которое бот отвечал прямо в группе («Отвечу подробнее в личных сообщениях» + кнопка) — при наплыве подписок это мелькало в группе у всех на виду. Бот не может первым написать в личку незнакомому пользователю (ограничение Telegram) — единственный официальный обход: заявки на вступление. В группе включено «Заявки на вступление» (Управление группой → Заявки на вступление); теперь `on_join_request()` (`ChatJoinRequestHandler`) сам одобряет заявку через `approve_chat_join_request()` и сразу пишет приветствие в личку через `req.user_chat_id` — Telegram разрешает это именно в момент обработки заявки, даже без предыдущего `/start`. Служебные сообщения о вступлении/выходе (`msg.new_chat_members`/`msg.left_chat_member`) в `on_message()` теперь просто игнорируются — в группе больше ничего не отвечаем. Требует, чтобы бот оставался администратором группы с правом одобрять заявки.

### YouTube-канал «Дыхание движения» (agents/youtube_agent.py + youtube_api.py)

Мультиагентная система для отдельного YouTube-канала (не путать с Telegram/VK Конфуцием):
- **ScriptAgent** — пишет сценарий (Shorts/Урок/Обзор), обязательная последняя реплика — устный CTA с названием программы «Бадуаньцзин за 21 день» на Boosty (ссылка в описании сама по себе почти не работает, особенно в Shorts).
- **SeoAgent** — заголовок/описание/теги/хэштеги строго в JSON, категория 26 (How-to) или 17 (Sports).
- **ThumbnailAgent** — превью 1280×720 через Pillow (тёмный/фиолетовый/минимал фон, лого канала). Если тема/заголовок содержит «день/урок/упражнение» + номер (цифрой или словом — «второе упражнение»), рисует бейдж-номер серии в левом верхнем углу (`_extract_episode_label`).
- **AnalyticsAgent** — читает реальную статистику канала через YouTube Data API и даёт 2–3 рекомендации.
- **YoutubeMaster** — оркестратор: тема → сценарий → SEO → превью → сохранение в БД (`youtube_videos`) → готово к загрузке.

`youtube_api.py` — OAuth2 (`YOUTUBE_CLIENT_ID/SECRET/REDIRECT_URI`, токены хранятся в `bot_config` под ключом `youtube_oauth`). Помимо загрузки (`upload_video`) поддерживает правку уже опубликованных видео: `get_video_snippet` подтягивает текущий snippet с YouTube (источник истины, а не локальная копия в БД, которая может разойтись с реальным описанием), `update_video` мержит переданные поля и пишет обратно. В админ-боте: «▶️ YouTube → 📋 История видео» → выбрать опубликованное видео → «✏️ Изменить название/описание» → бот применяет правку напрямую через уже существующую авторизацию, без ручного копипаста в Studio.

**Осторожно с формулировками про здоровье:** заголовки/описания не должны напрямую сравнивать эффект цигун с лекарствами («лучше таблеток» и т.п.) — риск попасть под политику YouTube о медицинской дезинформации, плюс подрывает доверие скептичного зрителя.

**Еженедельная аналитика (`_yt_digest_loop` в `admin_bot.py`, добавлено 13.07.2026):** по понедельникам после 10:00 МСК шлёт отчёт `AnalyticsAgent` всем `ADMIN_IDS`, тот же паттерн день-однократной отправки через `bot_config` (`yt_digest_date`), что уже был у `_growth_reminder_loop`. Без авторизации YouTube просто не шлёт отчёт, но всё равно помечает день отправленным — не долбит проверкой каждые 30 сек в цикле.

**Убран нерабочий декоративный элемент (13.07.2026):** `ThumbnailAgent._draw_bg_glyph` рисовал полупрозрачный иероглиф 氣 фоном на превью, используя шрифт `NotoSansCJK-Regular.ttc` — которого никогда не было в `fonts/` (только `DejaVuSans*.ttf`, без CJK-глифов), поэтому `if not font_path.exists(): return` тихо пропускал отрисовку на каждом превью с момента добавления. Открытый CJK-шрифт с полным набором глифов весит 10+ МБ ради одного декоративного символа — непропорционально, поэтому код удалён целиком, а не чинился добавлением шрифта.

**Заголовок нумерованных упражнений — зафиксированный шаблон (14.07.2026):** `SeoAgent` съехал со стиля
«Бадуаньцзин [словом] упражнение: техника «Название»» (упражнения 1–6) на сокращённое «Бадуаньцзин упр. N:
Название» для упражнений 7–8 — модель сама решила сократить, ничего в промпте это не запрещало явно.
Промпт теперь фиксирует точный шаблон и явно запрещает сокращение «упр.» и цифровую нумерацию вместо
словесной. Заодно закреплён единый регистр обращения к зрителю в описании («вы», не «ты»/«я» вперемешку
по видео) и добавлена явная проверка согласования слов — упражнение 8 до этого ушло в эфир с «Ключевые
момент» вместо «Ключевой момент».

**Баг: повторная загрузка видео на редеплое давала дубли на YouTube (исправлено 14.07.2026).** `USER_STATE`/
`USER_GENERATED` — это память процесса, не общая для инстансов бота. Если Railway на секунды-две держит
одновременно живыми старый и новый контейнер во время редеплоя (обычное дело при роллинг-деплое), оба
поллят Telegram и в узком окне гонки могут получить одно и то же сообщение с видео/ссылкой на Яндекс.Диск —
без проверки в БД оба независимо скачивали и загружали видео на YouTube, получались два разных
`youtube_id` для одного ролика, а `mark_youtube_published` в БД отслеживал только тот, что записался
последним — второе видео оставалось "осиротевшим" на канале, не привязанным ни к одной записи в
`youtube_videos`. Поймано на практике: видео из чата показало один `youtube_id`, а в БД лежал другой.
Исправлено через `claim_youtube_video_for_upload()` (`data/database.py`) — атомарный
`UPDATE ... SET status='uploading' WHERE status='pending' RETURNING id`: только один из двух
конкурирующих процессов реально "забирает" право на загрузку (Postgres гарантирует атомарность), второй
получает `False` и вежливо отказывается без повторной загрузки. При ошибке `reset_youtube_video_status()`
откатывает статус на `'pending'`, чтобы можно было попробовать снова — иначе видео застряло бы в
`'uploading'` навсегда после любого сбоя сети.

Список кладётся в `USER_GENERATED[uid]["dlg_list"]`, выбор диалога (`dlg_view_{idx}`) подгружает полную историю (`load_chat_history`) и присылает её админу, разбивая на сообщения по 3800 символов при необходимости.

## Стратегия роста — «Бадуаньцзин за 21 день»

Флагманский цифровой продукт внутри уже существующего Boosty (не новый сервис — структурирование того, что уже есть). Работаем по этому плану поэтапно, отмечая прогресс.

**Модель монетизации:** сам «Бадуаньцзин за 21 день» — бесплатный лид-магнит на Boosty, деньги с него не берутся. Задача воронки — затянуть зрителя на канал/в подписку Boosty, а зарабатывает отдельный платный тир/донат, не сама программа. Это важно для текста CTA и описаний видео — упор на «бесплатно», а не на цену.

**Реальный прогресс отмечается в самом боте**, не в чекбоксах ниже: меню «Стратегия роста» в admin_bot.py хранит подробный чек-лист по пунктам в таблице `growth_tasks` (с сохранением состояния между рестартами и ежедневным напоминанием админу о следующей невыполненной задаче после 10:00 МСК). Чекбоксы недель 1–4 в этом файле — только справочная канва плана, актуальный статус смотри в самом боте.

### Идея
21-дневная программа на Boosty: 8 упражнений Бадуаньцзин + дыхательная техника, с прогрессией по дням. Материал уже частично готов — в контент-плане есть темы «Полный комплекс Бадуаньцзинь — 8 упражнений», «Как правильно дышать в цигун». Техническая база по каждому упражнению (повторения, ключевые моменты, частые ошибки) — в `data/knowledge.py → BADUANJIN_TECHNIQUE`, переиспользуется и в промпте Конфуция, и в сценариях YouTube.
